# 作業ルール

## 基本方針

作業はかなり緩和し、Codexは止まりすぎずにどんどん進める。

ユーザーが「進めてください」「実行してください」「修正してください」「書き換えてください」と依頼した場合は、その依頼範囲を承認済みとして扱う。

作業前の細かい承認確認は原則不要。必要な確認は、作業中の短い報告または作業後のまとめで行う。

ただし、CodexアプリやOSが求める権限承認、外部サービスの認証、サンドボックス外実行の承認は別扱いで、必要になった時点で確認する。

## GitHub token の扱い

GitHub token はチャット本文へ貼らない。

pushで認証が必要な場合は、ユーザーがGitHub画面でtokenをコピーし、Codexはクリップボード経由で非表示入力として使う。実行ログや作業記録にはtoken本体を残さない。

Fine-grained personal access token は、送信先repoを正しく選ぶ。

- `reha1` のpushには `hirogari-toroku/reha1` への権限が必要。
- 統合台帳のpushには `hirogari-toroku/hirogari-system-ledger` への権限が必要。
- 通常のpushには `Contents: Read and write` が必要。
- `Metadata` はGitHub側で必須の `Read-only` のままでよい。

`Write access to repository not granted` が出た場合は、token自体は読めているが、対象repoへの書き込み権限が足りない可能性が高い。対象repoを選び直したtokenを用意する。

スクリーンショットや画面共有にtokenが写った場合は、そのtokenは削除または再生成する。

通常はmacOS KeychainへGitHub認証を保存しておき、毎回tokenを入力しない。

現在の標準設定:

```bash
git config --global credential.helper osxkeychain
git config --global credential.useHttpPath true
```

`credential.useHttpPath true` により、GitHub全体ではなくrepoパスごとに認証を分ける。これにより、`reha1` 用tokenと統合台帳用tokenを取り違えにくくする。

Keychainへ保存済みのrepo:

- `https://github.com/hirogari-toroku/reha1.git`
- `https://github.com/hirogari-toroku/hirogari-system-ledger.git`

token期限切れ、repo権限不足、Keychain未保存、別端末/別環境での作業時だけ、GitHub画面でtokenをコピーして保存し直す。

## GitHub台帳共有の事前承認

統合台帳 `https://github.com/hirogari-toroku/hirogari-system-ledger` は private repo として、プロジェクト内の作業記録・手順書・引き継ぎ情報を共有する保存先にする。

台帳内の `README.md` と `docs/` には、内部パス、スプレッドシートID、GAS script ID、GAS deployment ID、GitHub repo URL、現在の運用状態が含まれることがある。ユーザーはこの前提を理解したうえで、同 private repo への push を今後も承認済みとしている。

そのため、台帳の通常更新や作業記録更新を `hirogari-system-ledger` へ push する場合は、個別の事前確認で止めず、作業後に何をpushしたかを報告する。

例外として、個人情報、利用者・家族・スタッフの詳細な本番データ、秘密鍵、token、パスワード、API secret、OAuth credential、`.clasprc.json` などの認証情報を含む可能性がある場合は、private repo であってもpush前に内容を確認する。

## 報告だけで進めてよい操作

以下は、個別承認を待たずに進めてよい。

- ローカル手順書、台帳、スキルの作成・編集
- ローカルコードの調査・修正
- `rg`、`sed`、`git status`、`git diff` などの読み取りコマンド
- テスト、lint、ビルド、型チェック
- GASコードのローカル編集
- 管理者限定機能、トリガー設定用コード、メニュー相当処理の実装
- 既存挙動を確認するための読み取り中心のDrive、スプレッドシート、GitHub、GAS確認
- 少数の既知対象に対する確認・修正案の作成
- 統合台帳の作業記録・手順書・引き継ぎ情報を、private repo `hirogari-system-ledger` へpushする準備

## 進めてよいが、作業後に必ず報告する操作

以下は、依頼範囲内であれば進めてよい。作業後に、何を変えたか、どこに影響するか、追加確認が必要かを報告する。

- GASコード変更
- 管理者限定エンドポイント追加
- トリガー設定やメニュー相当処理の追加・調整
- 既存デプロイの更新
- GitHubへのpush
- 統合台帳の作業記録・手順書・引き継ぎ情報を private repo `hirogari-system-ledger` へpush
- GAS本番デプロイ
- スプレッドシートの構成に合わせたコード修正
- Drive上の既存ファイルや既存フォルダの場所確認
- 少数の既知ファイルの整理、移動、リネーム案作成
- 依頼範囲内の少数・既知対象へのDrive共有やスプレッドシート更新
- 給与明細PDFやGMO振込CSVなど、支払・振込に直結する本番成果物の作成

## 個別確認が必要な操作

以下だけは、実行直前に個別確認する。

- Driveフォルダの大量作成や大量共有
- 利用者・スタッフ・給与・入金などの本番データを広範囲に書き換える一括処理
- 外部送信を伴うLINE/Gmail通知の大量送信
- 削除、初期化、復元不能な変更
- ユーザーが「確認してから」「まだ実行しないで」と明示した操作

管理者限定のWebアプリ入口を追加する場合は、必ず既存の管理者判定を通し、匿名アクセス可能なWebアプリでも管理者以外が実行できない形にする。

## 変更のまとめ方

- コード全文は貼らず、必要な場合はファイルリンクで参照する。
- デプロイや高コストな確認は、クレジット消費を避けるため、できるだけまとめて行う。
- 手順として再利用する判断や注意点は、スキルまたはこの台帳に追記する。
