# 利用者登録手順

## 目的

利用者がLINE、LIFF、利用申請フォーム、利用者マスタ、重要事項説明に正しくつながるようにする。

## 基本方針

- 利用者登録はスタッフ登録とは分けて扱う。
- 利用者のGoogleメールは取得しない。
- LINE/LIFFで本人確認に使う情報を取得し、利用者マスタと結びつける。
- 高齢者などスマホ操作が難しい人には、紙での説明・手動管理を残す。

## 初回登録の流れ

### 1. LINE公式アカウントへ誘導

利用者または家族に、ひろがり公式LINEのQRコードを提示し、友だち追加してもらう。

作成済みのQRコード表示ページ:

```text
https://hirogari-toroku.github.io/reha1/?mode=qr
```

友だち追加後、利用者または家族に次を送ってもらう。

```text
1
```

この段階の役割:

- LINE公式アカウントの応答メッセージで、利用者登録用LIFFリンクを案内する。
- GAS側は `1` から `4` の番号メッセージには追加返信しない。
- LINEメッセージ側のLINEユーザーIDは、公式LINEメッセージ由来の情報として記録対象になる。

### 2. 利用者登録LIFFを開く

利用者または家族がLINE内の案内リンクから、利用者登録LIFFを開く。

作成済みの利用者登録LIFF入口:

```text
https://hirogari-toroku.github.io/reha1/?mode=register
```

実装上の設定:

- GitHub repo: `https://github.com/hirogari-toroku/reha1`
- ローカルHTML: `/Users/soichi/Documents/Codex/reha1/index.html`
- LIFF ID: `2010856600-yxOaV2Np`
- 利用申請Googleフォーム: `https://docs.google.com/forms/d/e/1FAIpQLSfxwcL2rCPAbkbmtPhxhzFdWBQeUyRh690JLXXmbUYZ3kDNnQ/viewform?usp=dialog`

Google Drive上の保管場所:

- `マイドライブ > 2利用者関連資料`
- フォーム本体: `リハビリ利用申請フォーム`
- 回答スプレッドシート: `リハビリ利用申請フォーム（回答）`

この段階の役割:

- LIFFログインを行う。
- LIFF用LINEユーザーIDを取得する。
- LINE表示名を取得する。
- `LINEユーザー一覧` と `LIFF操作ログ` に記録する。
- その後、利用申請Googleフォームへ自動で進む。

注意:

- フォーム回答より前に、LIFF用LINEユーザーIDを取得する。
- `1` を入力した瞬間にLIFF用LINEユーザーIDを取得するのではなく、利用者登録LIFFを開いた時点で取得する。

### 3. 利用申請フォームに回答

利用者または家族がGoogleフォームで基本情報を入力する。

フォーム内では、具体的な初回訪問日ではなく、訪問しやすい曜日と時間帯の希望を入力してもらう。

訪問希望曜日・時間帯の説明文案:

```text
スタッフは、平日18時以降（勤務後）または土日の方が比較的調整しやすい傾向があります。
ご都合のよい曜日・時間帯を、できるだけ複数ご記入ください。
```

交通費の事前案内文案:

```text
できるだけご希望に合うスタッフを調整しますが、訪問エリアや時間帯によっては、交通費が必要となる場合があります。
その場合は、事前または初回訪問時に内容をご説明します。
```

収集する主な情報:

- 利用者名
- 連絡先
- 住所
- 希望内容
- 訪問希望曜日
- 訪問希望時間帯
- 紹介者
- その他、訪問開始に必要な情報

### 4. フォーム回答後の取込

フォーム回答後、利用者アンケートを利用者マスタへ取り込む。

通常の自動処理:

```text
📌 自費リハ管理 -> ⚙️ 利用者登録フォーム自動処理を設定
```

このトリガーを設定すると、次回以降はフォーム回答後に自動で取込が走る。

復旧用の手動操作:

```text
📌 自費リハ管理 -> 📝 利用者アンケートを利用者マスタへ取込
```

方針:

- 自動処理では、利用者マスタへの取込、LINE情報との紐づけ候補確認、LINE情報反映、紹介者管理、LIFF表示用マスタ更新、利用者登録処理ログ記録まで行う。
- 通常の利用者登録手順に手動メニュー実行を含めない。
- フォーム回答後に自動処理されない場合だけ、管理者がメニュー実行またはログ確認を行う。

取込後に確認するもの:

- 利用者マスタに利用者が追加されている。
- 利用者マスタのLINE表示名、LINEユーザーID、LIFF用LINEユーザーIDが必要に応じて反映されている。
- 訪問希望曜日と訪問希望時間帯が確認できる。
- 紹介者が入力されている場合は、`紹介者マスタ` と `紹介管理` の確認対象になる。

### 紹介者情報の扱い

利用者登録フォームに紹介者が入力されている場合、データ整備時に利用者マスタ、紹介者マスタ、紹介管理へ反映する。

運用上の注意:

- 紹介者マスタに登録済みの紹介者は、紹介者IDと紹介者名を利用者マスタへ反映する。
- 紹介者マスタに未登録の場合は、紹介者確認として残し、あとから紹介者マスタを整える。
- 紹介料対象、紹介料支払状況、利用開始日は自動確定せず、運営確認を行う。

### 5. 訪問希望条件をスタッフへ共有

利用者から出た訪問希望曜日と時間帯を、スタッフグループLINEへ送る。

文面案:

```text
新規利用者様の訪問希望条件です。

訪問可能な方は回答をお願いします。

希望:
・曜日：○曜日、○曜日
・時間帯：午前、午後、○時頃

回答:
○ 訪問可能
△ 条件が合えば可能
× 不可

対応可能な方は、対応できる曜日・時間帯もあわせて回答をお願いします。
```

未確定・確認したい点:

- LINEの標準アンケート機能をAPIで自動作成できるかは未確認だったが、Messaging APIの通常機能ではアンケート作成用のAPIは見当たらない。
- 自動化する場合は、スタッフグループLINEへ募集メッセージを送り、回答はLIFFまたはGoogleフォームで回収する形が現実的。
- 手動運用では、通常メッセージへの返信で `○`、`△`、`×` と対応可能な曜日・時間帯を集める。

### 6. 担当スタッフを選定

スタッフグループLINEまたは回答フォームの結果を確認し、訪問可能なスタッフの中から担当スタッフを選定する。

判断材料:

- 利用者の希望日時
- スタッフの訪問可否
- 職種、経験、相性
- 訪問エリア
- 継続訪問できる見込み

担当スタッフが決まったら、スタッフと利用者の初回訪問候補日を具体化する。

### 7. 初回訪問日の候補を利用者へ提示

担当予定スタッフの訪問可能日を確認し、利用者の希望曜日・時間帯に合う候補日を作る。

その候補日を利用者または家族へ送り、選択してもらう。

遠方スタッフが候補になる場合:

- スタッフ宅から訪問場所までの距離を確認する。
- 交通費が発生する可能性がある場合は、訪問前、具体的には利用者または家族へ初回訪問候補日を選んでもらうタイミングで伝える。
- 候補日の案内には、追加交通費の目安も一緒に記載する。
- 利用者または家族が「追加交通費がかかるなら希望しない」を選べるようにする。
- 交通費が利用者からスタッフへ直接支払いになる場合は、初回訪問時の重要事項説明でスタッフから説明し、双方で確認する。

現時点の運用:

- 手動で候補日を送る。
- 利用者または家族に選んでもらう。
- 交通費が発生する候補の場合は、交通費の目安と「追加交通費がかかるなら希望しない」の選択肢も入れる。
- 決定した初回訪問日を記録する。

候補日案内の文面案:

```text
初回訪問の候補日時をご案内します。

以下からご都合のよい日時をお選びください。

候補:
・○月○日 ○時頃
・○月○日 ○時頃
・○月○日 ○時頃

なお、担当候補スタッフの訪問距離の関係で、別途交通費が必要となる場合があります。
交通費が発生する場合は、目安金額をあわせてご案内します。

追加交通費がかかる場合は希望しない、という選択も可能です。
```

将来の自動化候補:

- 担当スタッフの訪問可能日をもとに、利用者へ候補日選択フォームまたはLIFF画面を自動送信する。
- 利用者が候補日を選択したら、初回訪問予定を自動登録する。

初回訪問日が決まったら、スタッフと利用者を紐づける手順へ進む。

## スタッフ・利用者の紐づけ後

利用者とスタッフの紐づけができてから、重要事項説明の準備へ進む。

理由:

- 実際の担当スタッフが決まってから説明・初回予定調整を進める方がわかりやすい。
- 初回訪問時に、スタッフが重要事項説明動画を見せ、その後に同意フォームへ進んでもらう。
- 交通費が利用者からスタッフへ直接支払いになる場合は、初回訪問候補日を選んでもらうタイミングで事前に伝え、初回訪問時にもスタッフと利用者または家族の間で説明・確認・同意形成を行う。
- 将来的には、紐づけ完了時にLIFF表示用マスタ更新、重要事項説明リンク送信、スタッフへの銀行登録フォーム送信、初回訪問予定登録まで一括で自動化する。

## 重要事項説明

- 重要事項説明はLIFF入口から案内する。
- 登録済みスタッフまたは紐づき済み利用者だけ、LIFF画面上で重要事項説明リンクを表示する。
- 未登録者や認証途中の人には、PDF、動画、同意フォームのリンクを表示しない。
- 同意フォームは初回のみ送信する。
- 再確認する人には、フォーム再送信は不要だと伝える。
- 初回訪問時にスタッフが説明動画を見せ、その後に同意フォームへ進んでもらう。
- 交通費が発生する場合、特に利用者からスタッフへ直接支払ってもらう必要がある場合は、初回訪問時にスタッフが説明し、利用者または家族と確認する。

## 手動管理

LINE連携が難しい利用者は、手動管理として扱ってよい。

運用上の注意:

- 手動管理でも給与計算、実績集計、予定管理から漏れないようにする。
- 将来的には、利用者マスタに `LINE未連携・手動管理` のような状態を明示できるとよい。

## 確認項目

- 利用者マスタに利用者が登録されている。
- LINE情報が必要に応じて利用者マスタへ反映されている。
- 紐づき前の利用者にはスタッフ用操作が出ない。
- 重要事項説明リンクは、登録済み・紐づき済みの利用者だけに表示される。
- 同意フォームは初回同意記録として扱われている。
