# スタッフ・利用者 組み合わせ開始手順

## 目的

スタッフと利用者の組み合わせが決まった後、実際に訪問予定・実績登録を始められる状態にする。

この手順は、スタッフ初回登録や利用者初回登録とは別フェーズとして扱う。

## 開始前の確認

- スタッフがスタッフマスタに登録されている。
- スタッフのLIFF用LINEユーザーIDが登録されている。
- 利用者が利用者マスタに登録されている。
- 利用者の状態が `利用中` である。
- スタッフフォルダIDが入っている、または確認対象として整理されている。
- 利用者の訪問希望曜日と訪問希望時間帯が確認できている。

## 訪問希望条件の共有

利用者登録フォームで提示された訪問希望曜日と訪問希望時間帯を、スタッフグループLINEへ共有する。

文面案:

```text
新規利用者様の訪問希望条件です。

訪問可能な方は回答をお願いします。

希望:
・曜日：○曜日、○曜日
・時間帯：午前、午後、○時頃

回答:
○ 訪問可能
△ 条件が合えば可能
× 不可

対応可能な方は、対応できる曜日・時間帯もあわせて回答をお願いします。
```

運用メモ:

- Messaging APIの通常機能では、LINEの標準アンケートをAPIで自動作成する方法は見当たらない。
- 自動化する場合は、スタッフグループLINEへ募集メッセージを送り、回答はLIFFまたはGoogleフォームで回収する形を優先する。
- 手動運用では、通常メッセージへの返信で `○`、`△`、`×` と対応可能な曜日・時間帯を集める。
- 訪問可能なスタッフの中から、職種、経験、相性、訪問エリア、継続性を見て担当者を決める。

## 初回訪問日の決定

担当予定スタッフが決まったら、スタッフの訪問可能日を確認し、利用者の希望曜日・時間帯に合う具体的な候補日を作る。

その候補日を利用者または家族へ送り、選択してもらう。

遠方スタッフが候補になる場合:

- スタッフ宅から訪問場所までの距離を確認する。
- 交通費が発生する可能性がある場合は、訪問前、具体的には利用者または家族へ初回訪問候補日を選んでもらうタイミングで伝える。
- 候補日の案内には、追加交通費の目安も一緒に記載する。
- 利用者または家族が「追加交通費がかかるなら希望しない」を選べるようにする。
- 交通費が利用者からスタッフへ直接支払いになる場合は、初回訪問時の重要事項説明でスタッフから説明し、双方で確認する。

現時点の運用:

- 手動で候補日を送る。
- 利用者または家族に選んでもらう。
- 交通費が発生する候補の場合は、交通費の目安と「追加交通費がかかるなら希望しない」の選択肢も入れる。
- 決定した初回訪問日を記録する。

候補日案内の文面案:

```text
初回訪問の候補日時をご案内します。

以下からご都合のよい日時をお選びください。

候補:
・○月○日 ○時頃
・○月○日 ○時頃
・○月○日 ○時頃

なお、担当候補スタッフの訪問距離の関係で、別途交通費が必要となる場合があります。
交通費が発生する場合は、目安金額をあわせてご案内します。

追加交通費がかかる場合は希望しない、という選択も可能です。
```

将来の自動化候補:

- 担当スタッフの訪問可能日をもとに、利用者へ候補日選択フォームまたはLIFF画面を自動送信する。
- 利用者が候補日を選択したら、初回訪問予定を自動登録する。

## 紐づけ

1. 管理者がスタッフと利用者の組み合わせを決める。
2. `スタッフ利用者マスタ` に紐づけを登録する。
3. 利用者が終了・休止の場合は、表示対象にしない。
4. 担当スタッフが複数いる場合は、運用上必要な組み合わせだけ登録する。

管理者LIFFから紐づけする場合:

- 入口は `https://hirogari-toroku.github.io/reha1/?mode=admin`。
- `紐づけを追加` でスタッフと利用者を選び、`スタッフ利用者マスタ` に保存できる。
- 既存の紐づけは、スタッフ・利用者の選択を変更して保存できる。
- 誤登録は解除できる。解除後はLIFF表示用マスタも更新される。

注意:

- 管理者LIFFからの保存・解除はスプレッドシートを変更する。
- 対象スタッフ、対象利用者、対象行、解除してよい関係かを確認してから実行する。
- 紐づけ後は、スタッフ用画面と利用者用画面の代理表示で見え方を確認する。

## LIFF表示

紐づけ後、LIFF表示用マスタを更新する。

現時点の操作:

```text
📌 自費リハ管理 -> ⚡ LIFF表示用マスタを更新
```

確認項目:

- スタッフ用Webアプリに担当利用者が表示される。
- 終了・休止の利用者が表示されない。
- 利用者名横のカルテボタンなど、必要なリンクが出る。
- 予定外実績は閲覧中心で表示される。
- 管理者LIFFの代理表示テストで、スタッフ画面・利用者画面の予定表示を確認できる。

将来の自動化候補:

- スタッフと利用者を紐づけたタイミングで、LIFF表示用マスタを自動更新する。
- スタッフと利用者を紐づけたタイミングで、利用者へ重要事項説明リンクを自動連絡する。
- スタッフと利用者を紐づけたタイミングで、スタッフへ銀行登録フォームを自動送信する。
- 初回訪問日が決まっている場合は、初回訪問予定も自動登録する。

## 銀行登録フォーム

担当利用者が決まったスタッフには、銀行登録フォームを送る。

現時点の運用:

- 手動で送る。
- 口座登録フォーム回答後、スタッフマスタへ取り込む。
- 振込先登録状況を更新する。

将来の自動化候補:

- スタッフと利用者を紐づけたタイミングで、銀行登録フォームを自動送信する。

## 重要事項説明の案内

利用者とスタッフの紐づけができたら、重要事項説明の準備をする。

現時点の運用:

- 初回スタッフ訪問時に、スタッフが説明動画を見せる。
- 動画確認後、同意フォームへ進んでもらう。
- 交通費が発生する場合、特に利用者からスタッフへ直接支払ってもらう必要がある場合は、スタッフから説明し、利用者または家族と確認する。
- 同意フォームは初回のみ送信してもらう。
- スマホ操作が難しい場合は紙で説明し、必要な記録を残す。

将来の自動化候補:

- スタッフと利用者を紐づけたタイミングで、重要事項説明リンクを自動送信する。
- 重要事項説明の同意状況をLIFFまたは管理画面で確認できるようにする。

## スタッフへの案内

文面案:

```text
担当利用者の登録が完了しました。

次回からスタッフ用Webアプリを開くと、担当利用者の名前を選択できます。
今後は、訪問予定と訪問実績の登録をWebアプリからお願いします。

また、給与振込に必要な口座情報の登録フォームをお送りしますので、入力をお願いします。

もし利用者名が表示されない、登録できないなどがあれば教えてください。
よろしくお願いします。
```

## 初回動作確認

- スタッフがWebアプリを開ける。
- 担当利用者が表示される。
- 訪問予定を登録できる。
- 開始・終了の実績を登録できる。
- 登録後に確認LINEが届く。
- `予定・実績照合` に反映できる。
- スタッフフォルダが共有されている。
- 口座登録が必要な場合、振込先登録状況が確認できる。
