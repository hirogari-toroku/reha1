# 運営作業手順

## 目的

運営側が、スタッフ登録、利用者登録、紐づけ、表示更新、ログ確認を迷わず行えるようにする。

## 基本ルール

- 作業は止まりすぎないように進める。
- ユーザーが「進めてください」「実行してください」「修正してください」「書き換えてください」と依頼した場合は、その依頼範囲を承認済みとして扱う。
- ローカル手順書、スキル、コード調査、ローカルコード修正、GASコードのローカル編集は、個別承認を待たずに進めてよい。
- 実行直前に個別確認するのは、Driveフォルダの大量作成・大量共有、本番データの広範囲一括変更、大量LINE/Gmail送信、削除・初期化・復元不能な変更、ユーザーが「確認してから」「まだ実行しないで」と明示した操作だけにする。
- GitHub push、GAS本番デプロイ、給与・振込に直結する本番成果物作成は、依頼範囲内なら進めてよい。作業後に変更内容と影響を報告する。
- GitHub token はチャット本文へ貼らず、GitHub画面でコピーしたものをクリップボード経由で非表示入力する。repoごとに権限が必要で、`reha1` 用tokenでは台帳repoへpushできない。
- 管理者限定のWebアプリ入口や管理者限定処理を追加する場合は、既存の管理者判定を通し、匿名アクセス可能なWebアプリでも管理者以外が実行できない形にする。

## 管理者LIFF

入口:

```text
https://hirogari-toroku.github.io/reha1/?mode=admin
```

確認するもの:

- `管理者マスタ`
- `LINEユーザー一覧`
- `スタッフマスタ`
- `利用者マスタ`
- `スタッフ利用者マスタ`
- `LIFF表示用マスタ`

できること:

- データ整備の一括実行
- 利用者アンケート取込
- LINE情報のマスタ反映
- ID列整備
- LIFF表示用マスタ更新
- 回数券更新
- スタッフ登録フォーム自動処理トリガー設定
- 利用者登録フォーム自動処理トリガー設定
- スタッフ・利用者の代理表示テスト
- スタッフ利用者マスタの紐づけ追加・更新・解除
- 紐づけ保存後の担当開始準備状況確認
- 担当開始準備パネルからの銀行登録フォーム案内送信

注意:

- 管理者LIFFの代理表示テストは表示確認専用。開始、終了、予定変更、キャンセルは実行しない。
- 紐づけ保存・解除は `スタッフ利用者マスタ` を変更し、LIFF表示用マスタも更新する。
- 紐づけ保存後は、担当開始準備パネルでスタッフフォルダ共有、銀行登録、訪問希望、初回訪問予定などの不足を確認する。
- 銀行登録フォーム案内ボタンは、対象スタッフ1名へLINE送信する。送信前に画面上の確認ダイアログを出し、結果はログへ残す。
- 銀行登録フォーム案内ボタンが使えない場合は、スタッフのMessaging API LINEユーザーID、`振込先登録状況`、口座登録フォームURLの設定を確認する。
- スタッフ登録フォーム自動処理トリガー設定は、フォーム回答後のスタッフマスタ取込・スタッフフォルダ作成/共有・ログ記録を自動実行する。共有通知メールが届く可能性があるため、必要時だけ実行する。
- 利用者登録フォーム自動処理トリガー設定は、フォーム回答後の利用者マスタ取込、LINE情報反映、紹介者管理、LIFF表示用マスタ更新、利用者登録処理ログ記録を自動実行する。フォルダ作成や外部通知送信は行わない。
- 実行前に、対象スタッフ、対象利用者、対象行、変更後にLIFF表示へ出す内容を確認する。
- 管理者未登録の場合は、表示されたLIFF用LINEユーザーIDを `管理者マスタ` に登録する。

## データ整備一括実行

`✅ データ整備を一括実行` は、紐づけ確認の前に候補情報を最新化するための運営者向け処理。

含まれる処理:

- マスタID列を整える
- スタッフ登録フォーム回答をスタッフマスタへ取込
- 利用者アンケートを利用者マスタへ取込
- LINEユーザー一覧を更新
- LINEユーザー一覧をマスタへ反映
- 紹介者マスタ、紹介管理を更新
- 振込先登録状況を更新
- LIFF表示用マスタを更新

注意:

- 複数シートを変更するため、実行前に目的と影響範囲を確認する。
- フォルダ管理については、既存のスタッフフォルダIDを保持し、この一括処理では自動作成しない。
- 自動化済みの通常処理がある場合、一括実行は復旧・確認用として扱う。

## 紹介者管理

利用者マスタの紹介者欄をもとに、`紹介者マスタ` と `紹介管理` を整える。

確認するもの:

- `利用者マスタ` の `紹介者`、`紹介者ID`、`紹介者名`、`紹介元種別`
- `紹介者マスタ`
- `紹介管理`

注意:

- 紹介者マスタに一致する紹介者がいれば、利用者マスタへ紹介者IDと紹介者名を反映する。
- 紹介者マスタに未登録の場合は、`紹介者マスタ未登録` または `紹介者確認` として残す。
- 紹介料対象、紹介料支払状況、利用開始日は自動確定せず、運営確認を前提にする。

## スタッフ登録時

確認するもの:

- `LINEユーザー一覧`
- `LIFF操作ログ`
- `スタッフマスタ`
- `スタッフ登録処理ログ`
- スタッフフォルダID
- Gmail共有状況

主なメニュー:

```text
📌 自費リハ管理 -> 📁 既存スタッフフォルダIDを確認・反映
📌 自費リハ管理 -> 📁 新規スタッフフォルダを作成・共有
```

注意:

- スタッフ登録フォーム自動処理トリガーは設定済み。通常はフォーム回答後に、スタッフマスタ取込、スタッフフォルダ確認・共有、処理ログ記録が自動で行われる。
- スタッフや通常運用者の登録手順には、`📌 自費リハ管理` -> `⚙️ スタッフ登録フォーム自動処理を設定` の実行を含めない。
- もしフォーム回答後に処理されない場合は、システム管理側でトリガー設定、フォーム回答シート、`スタッフ登録処理ログ` を確認する。
- 2026-09-06に `contact@reha-hirogari.com` でclasp再認証済み。GitHub Actions用の `CLASPRC_JSON` も更新済みで、`Deploy GAS` 成功確認済み。
- Codexからの `clasp run` 直接実行は `NOT_FOUND` で失敗することがあるため、運用作業は管理者LIFFまたはスプレッドシートメニューからの実行を優先する。
- 既存スタッフのフォルダは新しく作らない。
- 既存値があるスタッフマスタ列は上書きしない。

## 利用者登録時

確認するもの:

- `LINEユーザー一覧`
- `LIFF操作ログ`
- `利用者マスタ`
- 利用申請フォーム回答
- 訪問希望曜日
- 訪問希望時間帯
- 重要事項説明同意フォーム回答

主なメニュー:

```text
📌 自費リハ管理 -> 📝 利用者アンケートを利用者マスタへ取込
📌 自費リハ管理 -> 🧑 LINEユーザー一覧を更新
📌 自費リハ管理 -> 🔗 LINEユーザー一覧をマスタへ反映
```

注意:

- 利用者のGoogleメールは取得しない。
- LINE連携できない利用者は手動管理を残す。
- 利用者登録は、公式LINEで友だち追加してもらい、`1` を送ってもらうところから始める。
- `1` への応答で利用者登録LIFFを案内し、LIFF経由で利用申請フォームへ進んでもらう。
- 利用者登録フォーム自動処理トリガーは設定済み。通常はフォーム回答後に、利用者マスタ取込、LINE情報反映、紹介者管理、LIFF表示用マスタ更新、利用者登録処理ログ記録が自動で行われる。
- 自動化後は、通常の利用者登録手順に `📌 自費リハ管理` -> `📝 利用者アンケートを利用者マスタへ取込` の実行を含めない。
- フォーム回答後に自動処理されない場合だけ、管理者がメニュー実行またはログ確認を行う。
- 利用者登録フォームでは、具体的な初回訪問日ではなく、訪問希望曜日と訪問希望時間帯を入力してもらう。
- 利用者登録フォームでは、訪問エリアや時間帯によって交通費が必要となる場合があることを事前案内する。
- 訪問希望条件は、担当スタッフ選定のためスタッフグループLINEへ共有する。
- 重要事項説明は、スタッフと利用者の紐づけ後に案内する。

## 訪問希望条件と担当スタッフ選定

利用者登録フォームで訪問希望曜日と訪問希望時間帯が出たら、スタッフグループLINEに共有する。

文面案:

```text
新規利用者様の訪問希望条件です。

訪問可能な方は回答をお願いします。

希望:
・曜日：○曜日、○曜日
・時間帯：午前、午後、○時頃

回答:
○ 訪問可能
△ 条件が合えば可能
× 不可

対応可能な方は、対応できる曜日・時間帯もあわせて回答をお願いします。
```

確認すること:

- Messaging APIの通常機能では、LINEの標準アンケートをAPIで自動作成する方法は見当たらない。
- 自動化する場合は、スタッフグループLINEへ募集メッセージを送り、回答はLIFFまたはGoogleフォームで回収する形を優先する。
- 手動運用では、通常メッセージへの返信で `○`、`△`、`×` と対応可能な曜日・時間帯を集める。
- 訪問可能なスタッフの中から、職種、経験、相性、訪問エリア、継続性を見て担当者を決める。

## 初回訪問日の決定

担当予定スタッフが決まったら、スタッフの訪問可能日を確認し、利用者の希望曜日・時間帯に合う具体的な候補日を利用者または家族へ送る。

利用者または家族が候補日を選択したら、初回訪問日を決定し、必要に応じて初回訪問予定として登録する。

遠方スタッフが候補になる場合は、スタッフ宅から訪問場所までの距離を確認し、利用者または家族へ初回訪問候補日を選んでもらうタイミングで、交通費が発生する可能性と目安金額を伝える。

このとき、候補日選択の中に「追加交通費がかかるなら希望しない」という選択肢も残す。

将来の自動化候補:

- 担当スタッフの訪問可能日をもとに、利用者へ候補日選択フォームまたはLIFF画面を自動送信する。
- 利用者が候補日を選択したら、初回訪問予定を自動登録する。

## スタッフ・利用者紐づけ時

確認するもの:

- スタッフマスタ
- 利用者マスタ
- スタッフ利用者マスタ
- LIFF表示用マスタ

主なメニュー:

```text
📌 自費リハ管理 -> ⚡ LIFF表示用マスタを更新
```

将来の自動化候補:

- 初回訪問日が決まっている場合は、初回訪問予定も自動登録する。

現時点で自動化済み・表示済みのこと:

- 管理者LIFFで紐づけを保存すると、LIFF表示用マスタは自動更新される。
- 保存直後と紐づけ一覧内に、担当開始準備パネルが表示される。
- 担当開始準備パネルでは、スタッフ/利用者LINE連携、利用者状態、スタッフフォルダ共有、銀行登録、訪問希望、初回訪問予定、重要事項説明リンク設定を確認できる。
- 銀行登録が未完了でスタッフのMessaging API LINEユーザーIDがある場合、担当開始準備パネルから銀行登録フォーム案内を送信できる。
- 重要事項説明リンクはLINEリッチメニューとLIFF画面で案内できているため、自動送信はしない。

## 重要事項説明

主なメニュー:

```text
📌 自費リハ管理 -> 📘 重要事項説明マスタを整える
📌 自費リハ管理 -> ⚡ LIFF表示用マスタを更新
```

確認するもの:

- PDF URL
- 説明動画URL
- 同意フォームURL
- 登録済みスタッフ・紐づき済み利用者だけにLIFF画面上で表示されること
- 初回スタッフ訪問時に、スタッフが説明動画を見せ、その後に同意フォームへ進んでもらうこと
- 交通費が利用者からスタッフへ直接支払いになる場合は、初回訪問候補日を選んでもらうタイミングで事前に伝え、初回訪問時にもスタッフが説明し、利用者または家族と確認すること

## 例外対応

- 登録したのに未登録表示が残る場合は、LIFF用LINEユーザーIDの列と値を確認する。
- 担当利用者が表示されない場合は、スタッフ利用者マスタとLIFF表示用マスタ更新を確認する。
- フォーム回答後に自動処理されない場合は、フォーム送信トリガー設定と各登録処理ログを確認する。
- フォルダ共有が届かない場合は、Gmailアドレス、スタッフフォルダID、スタッフ登録処理ログを確認する。
