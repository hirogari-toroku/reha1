## 作業ルールの現在方針

- ユーザーが「進めてください」「実行してください」「修正してください」「書き換えてください」と依頼した範囲は、承認済みとして進める。
- ローカル手順書、スキル、コード調査、ローカルコード修正、GASコードのローカル編集は個別承認を待たずに進めてよい。
- GitHub push、GAS本番デプロイ、依頼範囲内の本番反映は進めてよい。作業後に内容と影響を報告する。
- 統合台帳の作業記録・手順書・引き継ぎ情報には、内部パス、スプレッドシートID、GAS script ID、GAS deployment ID、GitHub repo URL、現在の運用状態が含まれることがある。ユーザーはこの前提を理解し、private repo `https://github.com/hirogari-toroku/hirogari-system-ledger` へのpushを今後も承認済みとしている。
- 実行直前に個別確認するのは、Driveフォルダの大量作成・大量共有、本番データの広範囲一括変更、大量LINE/Gmail送信、削除・初期化・復元不能な変更、またはユーザーが明示的に止めた作業。
- 個人情報、利用者・家族・スタッフの詳細な本番データ、秘密鍵、token、パスワード、API secret、OAuth credential、`.clasprc.json` などの認証情報を含む可能性がある場合は、private repo であってもpush前に内容を確認する。
- GitHub token はチャット本文へ貼らず、GitHub画面でコピーしてから、Codex側でクリップボード経由の非表示入力として使う。
- Fine-grained token は送信先repoごとに権限が必要。`reha1` 用tokenでは台帳repoへpushできないため、台帳pushには `hirogari-toroku/hirogari-system-ledger` を選び、`Contents: Read and write` を付ける。

### 2026-09-09: 回数券基準を入金日基準でシステム更新する実装

- 回数券基準は、運用者が手で都度合わせるのではなく、`🎫 回数券を更新` 実行時にシステム側で更新する方針にした。
- 照合済み入金がある利用者について、最新入金日を `回数券基準` の基準日にし、入金日当日までの入金・利用を反映した残数を基準残数として保存する。
- 例: 入金前0回で30,000円入金された場合、基準日は入金日、基準残数は4回。次回以降は、その基準日より後の訪問だけが差し引かれる。
- 残数がプラスでもマイナスでも、入金日までの確認済み入金・利用を反映した実残数を基準残数に保存するため、その後の自動集計で引き継げる。
- GAS `importGmoNyushukkinFromPasteCore_()` に `rollCouponBaselinesAfterConfirmedPayments_()` を追加し、入金取込・重複整理・利用者照合後、回数券管理更新前に `回数券基準` をロール更新するようにした。
- 管理者LIFFの `adminRunCouponAll` とスプレッドシートメニューの `🎫 回数券を更新` は同じ中核処理を通るため、どちらから実行しても同じ方針で反映される。

### 2026-09-08: GitHub認証のKeychain保存

- GitHub push のたびにtoken入力が必要になっていた原因を確認した。
- 確認結果:
  - `credential.helper` が未設定だった。
  - GitHub CLI `gh` は未インストールだった。
  - `reha1` と統合台帳のremoteはどちらもHTTPSだった。
  - macOSの `git credential-osxkeychain` は利用可能だった。
- 対応:
  - `git config --global credential.helper osxkeychain` を設定した。
  - `git config --global credential.useHttpPath true` を設定した。
  - 台帳repo `hirogari-toroku/hirogari-system-ledger.git` 用tokenをmacOS Keychainへ保存した。
  - `reha1` repo `hirogari-toroku/reha1.git` 用tokenをmacOS Keychainへ保存した。
- 結果:
  - 台帳の手順書・作業記録更新 commit `15a1add Update handoff docs after bank guide work` をpush済み。
  - `reha1` の手順書同期 commit `a8b8f19 Sync project procedure docs` をpush済み。
  - 両repoとも `main` と `origin/main` が同期済み。
- 今後の運用:
  - 通常のpushでは毎回tokenをコピーしなくてよい見込み。
  - token期限切れ、Keychain未保存、repo権限不足、または別端末/別環境での作業時だけ、GitHub画面でtokenをコピーして保存し直す。
  - `Write access to repository not granted` が出た場合は、repo選択または `Contents: Read and write` 権限を確認する。
