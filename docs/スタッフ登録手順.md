# スタッフ登録手順

## 目的

スタッフが自費リハ管理システムを使えるように、LINE公式アカウント、LIFF、スタッフ登録フォーム、スタッフマスタ、スタッフフォルダをつなぐ。

この手順は大きく2段階に分ける。

1. スタッフ初回登録
2. 利用者が決まった後の運用開始

## スタッフ初回登録

### 1. LINE公式アカウントへ誘導

スタッフに、ひろがり公式LINEのQRコードを提示し、友だち追加してもらう。

作成済みのQRコード表示ページ:

```text
https://hirogari-toroku.github.io/reha1/?mode=qr
```

GitHub Pages内のQR画像:

```text
https://hirogari-toroku.github.io/reha1/assets/hirogari-line-qr.png
```

友だち追加後、スタッフに次を送ってもらう。

```text
4
```

この段階の役割:

- LINE公式アカウントの応答メッセージで、スタッフ登録用LIFFリンクを案内する。
- GAS側は `1` から `4` の番号メッセージには追加返信しない。
- LINEメッセージ側のLINEユーザーIDは、公式LINEメッセージ由来の情報として記録対象になる。

### 2. スタッフ登録LIFFを開く

スタッフがLINE内の案内リンクから、スタッフ登録LIFFを開く。

作成済みのスタッフ登録LIFF入口:

```text
https://hirogari-toroku.github.io/reha1/?mode=staff-register
```

実装上の設定:

- GitHub Pages本体: `https://hirogari-toroku.github.io/reha1/`
- GitHub repo: `https://github.com/hirogari-toroku/reha1`
- ローカルHTML: `/Users/soichi/Documents/Codex/reha1/index.html`
- LIFF ID: `2010856600-yxOaV2Np`
- スタッフ登録Googleフォーム: `https://docs.google.com/forms/d/e/1FAIpQLSfTjEQpVCXOUO5igr02E5yn_QnbuIUY9KoXvb2_VyxjCcxmYA/viewform?usp=dialog`

この段階の役割:

- LIFFログインを行う。
- LIFF用LINEユーザーIDを取得する。
- LINE表示名を取得する。
- `LINEユーザー一覧` と `LIFF操作ログ` に記録する。
- その後、スタッフ登録Googleフォームへ自動で進む。

注意:

- フォーム回答より前に、LIFF用LINEユーザーIDを取得する。
- `4` を入力した瞬間にLIFF用LINEユーザーIDを取得するのではなく、スタッフ登録LIFFを開いた時点で取得する。

### 3. スタッフ登録フォームに回答

スタッフがGoogleフォームで基本情報を入力する。

初回スタッフ登録フォームで扱う主な情報:

- 氏名
- 電話番号
- Gmailアドレス
- 住所
- 職種
- 経歴
- 資格
- 最終学歴
- 生年月日
- その他希望など

初回では原則として扱わない情報:

- 銀行名
- 支店番号
- 口座番号
- 口座名義カナ

銀行情報は、実際に利用者が割り当てられてから、別の銀行登録フォームで入力を促す。

### 4. フォーム回答後の自動処理

スタッフ登録フォームの回答後、GASのフォーム送信トリガーで自動処理が動く想定。

自動処理の内容:

- スタッフ登録フォーム回答を読む。
- スタッフマスタに同じ氏名があるか確認する。
- 未登録ならスタッフマスタへ追加する。
- 既存スタッフなら、空欄の基本情報だけ補完する。
- `LINEユーザー一覧` に同じ表示名または氏名候補があれば、LINE情報も同時反映する。
- スタッフIDを整える。
- スタッフ登録処理ログに結果を残す。

方針:

- 既存データは消さない。
- 同じスタッフ名は重複追加しない。
- 既存値がある欄は上書きしない。
- 初回登録では銀行情報を取り込まない。

確認ポイント:

- スタッフ登録フォーム自動処理トリガーは設定済み。
- 通常はスタッフがフォームに回答すると、スタッフマスタ取込、スタッフフォルダ確認・共有、処理ログ記録が自動で行われる。
- スタッフや通常運用者の登録手順には、`📌 自費リハ管理` -> `⚙️ スタッフ登録フォーム自動処理を設定` の実行を含めない。
- もしフォーム回答後に処理されない場合は、システム管理側でトリガー設定、フォーム回答シート、`スタッフ登録処理ログ` を確認する。

### 5. スタッフフォルダ確認・共有

フォーム回答後の自動処理内で、スタッフフォルダも確認される。

流れ:

1. `スタッフフォルダID` が空欄のスタッフだけ対象にする。
2. `スタッフ一覧` と `休止中スタッフ` から既存フォルダを探す。
3. 既存フォルダがあれば、そのIDを使う。
4. 既存フォルダがなければ、新規スタッフフォルダを作成する。
5. フォーム回答のGmailアドレスへ共有する。
6. `スタッフ登録処理ログ` に結果を記録する。

重要方針:

- スタッフフォルダと給与明細フォルダは同じ。
- 給与明細PDFはスタッフフォルダへ入れる。
- 既存スタッフのフォルダは新しく作らない。
- Drive上のフォルダ構成は今の運用を維持する。

### 6. 初回登録完了

ここまでで、スタッフの初回登録は完了。

この時点では、まだ担当利用者がいない場合がある。Webアプリを開いても利用者名が表示されないことがあるが、担当利用者が未設定なら正常。

## 利用者登録との関係

利用者登録フォームでは、具体的な初回訪問日ではなく、訪問希望曜日と訪問希望時間帯を出してもらう。

管理者は、その訪問希望条件をスタッフグループLINEへ共有し、訪問可能なスタッフを確認する。

スタッフ側の回答方法:

- `○`: 訪問可能
- `△`: 条件が合えば可能
- `×`: 不可

Messaging APIの通常機能では、LINEの標準アンケートをAPIで自動作成する方法は見当たらないため、自動化する場合は、スタッフグループLINEへ募集メッセージを送り、回答はLIFFまたはGoogleフォームで回収する形を優先する。

手動運用では、通常メッセージへの返信で可否を集める。

訪問可能なスタッフの中から担当スタッフが決まったら、スタッフの訪問可能日を確認し、利用者へ具体的な初回訪問候補日を提示する。利用者が候補日を選択した後、スタッフと利用者を紐づける手順へ進む。

遠方スタッフが候補になる場合:

- スタッフ宅から訪問場所までの距離を確認する。
- 交通費が発生する可能性がある場合は、利用者または家族へ初回訪問候補日を選んでもらうタイミングで伝える。
- 候補日の案内には、追加交通費の目安も一緒に記載する。
- 利用者または家族が「追加交通費がかかるなら希望しない」を選べるようにする。
- 交通費が利用者からスタッフへ直接支払いになる場合は、初回訪問時の重要事項説明でスタッフから説明し、双方で確認する。

## 利用者が決まった後

### 7. スタッフと利用者を紐づける

利用者が決まったら、管理者側でスタッフと利用者を紐づける。

確認するもの:

- スタッフマスタ
- 利用者マスタ
- スタッフ利用者マスタ
- LIFF表示用マスタ

このタイミングは初回登録とは時間が空くことがあるため、別手順として扱う。

### 8. 銀行登録フォームを送る

担当利用者が決まったスタッフに、銀行登録フォームを送る。

現時点の運用:

- 手動で送る。
- 回答後、口座登録フォームの回答をスタッフマスタへ取り込む。
- スタッフ名でスタッフマスタと結びつける。
- 振込先登録状況を更新する。

将来の自動化候補:

- スタッフと利用者を手動で紐づけたタイミングで、銀行登録フォームを自動送信する。
- あわせて、LIFF表示用マスタ更新、利用者への重要事項説明リンク送信、初回訪問日が決まっている場合の初回訪問予定登録も自動化したい。

### 9. 口座情報と受取人名の確認

実際の給与振込では、銀行側で登録されている受取人名と、振込CSV側の受取人名が異なると、振込エラー、返戻、金融機関側の確認対象になる可能性がある。

運用上の注意:

- 口座登録フォームでは、銀行名、支店名または支店番号、預金種目、口座番号、口座名義カナを確認する。
- 口座名義カナは半角カナへ変換する。
- 受取人名が未入力、またはスタッフマスタ既存値と食い違う場合は、振込先登録状況を `要確認` にする。
- 給与振込CSVを作成する前に、`振込先登録状況` が未登録または要確認のスタッフを確認する。
- 実際の振込エラー時の扱い、組戻し、手数料、再振込の手順は銀行の仕様に従う。必要時はGMOあおぞらネット銀行の最新案内を確認する。

### 10. LIFF表示用マスタを更新

担当利用者を紐づけた後、LIFF表示用マスタを更新する。

現時点の操作:

```text
📌 自費リハ管理 -> ⚡ LIFF表示用マスタを更新
```

将来の自動化候補:

- スタッフと利用者を紐づけたタイミングで、LIFF表示用マスタも自動更新する。
- あわせて、スタッフへの銀行登録フォーム送信、利用者への重要事項説明リンク送信、初回訪問日が決まっている場合の初回訪問予定登録も自動化したい。

### 11. スタッフへ利用開始案内

利用者の紐づけが終わったら、スタッフへ案内する。

文面案:

```text
登録ありがとうございます。

担当利用者の登録が完了しました。
次回からスタッフ用Webアプリを開くと、担当利用者の名前を選択できます。

今後は、訪問予定と訪問実績の登録をWebアプリからお願いします。

また、給与振込に必要な口座情報の登録フォームをお送りしますので、入力をお願いします。

もし利用者名が表示されない、登録できないなどがあれば教えてください。
よろしくお願いします。
```

### 12. 動作確認

確認項目:

- スタッフがWebアプリを開ける。
- 担当利用者が表示される。
- 訪問予定を登録できる。
- 開始・終了の実績を登録できる。
- 登録後に確認LINEが届く。
- `スタッフ登録処理ログ` にエラーがない。
- スタッフフォルダが共有されている。
- 銀行登録後、振込先登録状況が `登録済み` または確認済みの状態になっている。
